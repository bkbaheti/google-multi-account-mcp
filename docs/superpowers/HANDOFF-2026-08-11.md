## Why the branch exists

It started as "let's build an end-to-end test harness" and turned into fixing the OAuth permission model, because designing the harness surfaced two live bugs.

The model asserted things about Google's scopes that are false. The root cause each time was checking scope **description** pages ("View and download all your Drive files") instead of per-method **authorized scopes** lists. That mistake has now been made three times in this codebase, in both directions — first claiming scopes imply each other when they don't, then refusing calls Google actually permits.

**If you change a gate or an implication, verify it against the method's reference page.** Do not reason from the scope description, and do not trust this repo's own comments — several of them were confidently wrong.

## Deferred findings

Real, recorded, not blocking. The first is the only one with a subtlety worth reading before acting.

1. **Drive write tools keep the generic error.** Do **not** naively extend `DRIVE_FILE_NOT_VISIBLE` to them. Adding `drive:read` would not fix a *write* failure on an out-of-reach file — `drive.readonly` grants read only, and writing to a client-shared file needs Google's broad `drive` scope this project deliberately never requests. Extending needs *different* messaging, not the same remedy.
2. `driveApiError` / `gmailApiError` / `calendarApiError` are dead code — zero call sites.
3. Whether Google-side 403s deserve an error code distinct from our own gate refusals. They currently share one.
4. `src/server/index.ts` tool handlers have no direct unit coverage. Pre-existing, project-wide.
5. `capabilities.ts` implication expansion is a single pass, not a transitive closure. Correct for the one entry that exists; a future two-level chain would silently under-derive.
6. Drive and Calendar tool files name the injected gate parameter `validateAccountScope`; Gmail names it `requireCapability`. Same function, cosmetic inconsistency.
7. A ninth `mail:labels` capability was proposed and deferred pending verification of `users.labels.create/patch/delete`.
